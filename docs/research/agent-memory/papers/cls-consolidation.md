# Complementary learning systems: fast hippocampal store, slow neocortical store, replay, schema-dependent consolidation (McClelland, McNaughton & O'Reilly 1995; Kumaran, Hassabis & McClelland 2016)
Sources read: Kumaran et al. 2016 (http://stanford.edu/~jlmcc/papers/KumaranHassabisMcC16CLSUpdate.pdf, PDF text; sections "Replay of hippocampal memories and interleaved learning", "Rapid schema-dependent consolidation"). McClelland et al. 1995 downloaded as a scanned PDF, not read. Shin et al. 2017 for the AI instantiation (`generative-replay.md`). Sleep literature (Klinzing, Niethard, Born 2019) was paywalled and is NOT read here.

**Problem it solves.** Learning structured knowledge by gradual, interleaved updates of shared weights generalises but suffers *catastrophic interference* when new information arrives quickly; a second fast system stores episodes separately so that the slow system can be trained by **interleaved replay** of old and new items.

**Mechanisms (no closed-form equations in the paper).**
- Fast system (hippocampus): sparse, pattern-separated, one-shot storage of specific episodes; supports pattern completion from partial cues (`pattern-separation-completion.md`).
- Slow system (neocortex): small-learning-rate updates, structure extraction. Consolidation = hippocampus **replays** episodes (during rest/sleep) to the neocortex interleaved with other recent and old experiences.
- 2016 update: (i) replay is **not uniform**: it is goal-dependent, weighted by reward and novelty ("modulated by reward or novelty", Highlights), i.e. prioritised replay; (ii) recurrent hippocampal activity supports some generalisation (REMERGE, Kumaran & McClelland 2012); (iii) **schema-consistent information is integrated rapidly into the neocortex without disrupting existing knowledge, whereas schema-inconsistent information is acquired slowly and requires interleaved training with already-known examples** (simulation reproducing the event-arena experiments; "Rapid schema-dependent consolidation").

**Mapping to neocortex (the project is named after the slow system).** episodes/memories + vec0 vectors = fast store (hippocampus; append-only, raw, separated); entities, canonical predicates, relation facts, communities = slow store (neocortex; shared structure).

**What an SQLite + embedding system implements (LLM-free).**
1. **Consolidation worker (replay).** A background job selects a replay batch of memories with probability proportional to `priority = surprise * (1 + feedback) * 1/(1 + replay_count)` plus a uniform share of old memories (interleaving), and re-runs the *current* extraction/resolution over them (rules tier now, GLiNER later), merging entities, promoting stable predicate aliases, rebuilding links/communities. This is how improved extractors repair old memories without re-ingesting. Touches a new `consolidate` pass in `engine.rs`; reuses `remember.rs::prepare`/`resolve.rs`.
2. **Schema-consistency gate at write.** Define the schema as per-entity-type predicate statistics (which predicates occur for type `person`, expected cardinality, object types). On `remember`: if the new relation matches (known predicate group for this type, object type compatible, no live exclusive clash) write directly to the slow store; if inconsistent (new predicate for the type, type clash, contradicts a live exclusive fact), store the episode only, flag `conflict_candidate` and queue for replay with the older related facts interleaved before any supersession is committed. This is exactly the failure mode of REL-19 (a typo'd target retires the correct fact): the cure is slow integration of schema-inconsistent input.
3. **Interleaving when re-clustering**: when rebuilding communities or entity merges, mix a sample of old memories with recent ones in the pass so that recent bursts do not dominate community structure.

**Evidence.** Behaviour and neural recordings summarised in the review; simulation of schema-dependent learning (Kumaran et al. 2016 Box). For LLM memories, no paper here tests prioritised-replay consolidation; Mem0/A-Mem "evolve" notes with an LLM but without replay prioritisation.

**Weak / wrong.** The theory is about weights in neural networks, not symbolic stores; "replay priority" is stated qualitatively; my formulae for priority are (inference).

**What neocortex could steal, concretely.** A background `consolidate` pass in `engine.rs` with prioritised, interleaved replay, and a schema-consistency gate in `remember.rs::write_prepared` that defers supersession of schema-inconsistent writes. No LLM.

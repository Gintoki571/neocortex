# Cross-encoder reranker (lane nc-rerank)

Status: implemented, **opt-in** (`Config::rerank_top = 0`; `NEOCORTEX_RERANK=<N>` or
`--set rerank_top=<N>` turns it on). No new crate. Measured 2026-10-25/26 on base
`5270b44`, UltraBERT-Embed-150M, 12-core CPU.

## Decision

Default OFF. The release rule was "default ON only if fixtures AND holdout do not
regress beyond -0.005 and multihop-holdout2 improves". Fixtures and holdout do not
regress (MRR rises), but multihop-holdout2 does not improve (acc@10 0.820 -> 0.810
in every one of the six configs tried, one query), and recall latency rises far
more than the 10% allowed (see Latency). On the multi-hop world it also lowers
recall of the supporting-hop memories (acc@10 unchanged). The paraphrase gap the
lane targeted is not closed: the synonym / paraphrase categories do not move.

## Model

`cross-encoder/ms-marco-MiniLM-L-6-v2` (BERT, 6 layers, 384 hidden, 12 heads,
22.7M parameters, one logit). License: **Apache-2.0** (model card front matter,
`license: apache-2.0`). Source: `https://huggingface.co/cross-encoder/ms-marco-MiniLM-L-6-v2/resolve/main/<file>`;
files `model.safetensors` (90 870 598 bytes, sha256
`821d1aa69520101d6e0737f78a042ae25b19e5cb9160701909d10434f4aeb0ae`), `config.json`,
`tokenizer.json`, plus `tokenizer_config.json`, `vocab.txt`,
`special_tokens_map.json`, `README.md` (model card). Directory used here:
`rag/ms-marco-MiniLM-L-6-v2/` (model-artifact dir like `UltraBERT-Embed-150M/`);
runtime lookup is `NEOCORTEX_RERANK_MODEL`, else
`~/.neocortex/models/ms-marco-MiniLM-L-6-v2`.

## Implementation

- `src/rerank.rs`: `Reranker` trait, `CrossEncoder` (candle forward pass in the
  style of `src/ultrabert.rs`; post-LN BERT, exact-erf GELU, pooler dense+tanh,
  classifier), `LazyReranker` (loads on first use, caches success or error), and
  `blend`. Pairs are tokenised with the model's own `tokenizer.json`
  (`[CLS] q [SEP] text [SEP]`, token types 0/1), truncated to 256 tokens
  (longest side first), grouped by length and batched.
- `recall` (after fusion and modifiers, before MMR): the top `rerank_top` fused
  candidates are scored with (query, memory content) and re-sorted by
  `(1 - w) * fused_norm + w * sigmoid(logit)` (`w = w_rerank`, default 0.5;
  `fused_norm` is min-max over the head). The head keeps its original score range,
  so the tail stays below it.
- Skipped when `history` is true (history intent, `include_history`, `as_of`): the
  model reads text, not validity, and demotes the ended memory that is the answer.
  Measured: without this skip fixtures MRR fell 0.896 -> 0.871 (history 0.929 ->
  0.667, as-of 1.000 -> 0.905) and holdout MRR 0.791 -> 0.785 (history 0.833 -> 0.648).
- Model absent, unreadable or wrong shape: `LazyReranker::score` returns an error,
  `recall` ignores it and the output is identical to `rerank_top = 0`
  (`tests/rerank.rs::absent_model_recall_equals_reranker_off`).

## Numeric parity

`tests/rerank.rs` (model-gated: skips when the model directory is absent) against
`tests/fixtures/rerank_fixture.json`, 12 pairs (model-card pairs, memory-like
statements, accented text, a >256-token pair that is truncated, a 1-token text)
generated by transformers 5.20.2 / torch 2.14.1 fp32 with
`tests/fixtures/gen_rerank_fixture.py` (`AutoModelForSequenceClassification`,
`max_length=256`):

- max abs logit diff vs transformers: **3.93e-6** (limit 1e-3), scored one query
  at a time in padded batches.
- model-card sentence-transformers example `[8.607138, -4.320078]`: diff
  **1.9e-6 / 9.5e-7**.
- batching: each text scored alone vs together, < 1e-3.

Every other category (keyword, paraphrase, synonym, history, as-of,
current-vs-superseded, temporal-window, aggregation, distractor, single-hop) is
unchanged at w 0.3-0.7. The synonym and paraphrase queries that fail today
(for example "What does the chief investigator sip first thing?") keep failing:
the cross-encoder does not rank their gold memory high enough to cross the cut.
At w 1.0 (pure cross-encoder order) the same categories collapse (holdout
synonym recall 0.80 -> 0.40, paraphrase MRR 0.463 -> 0.358, multi-hop recall
0.889 -> 0.556), so the model is weaker than the fused retrieval on this
short-statement domain and only works as a light tie-breaker.

World multi-hop recall falls because chain memories ("X was born in Y") share no
words with the question, so the cross-encoder scores them low and demotes the
path/sem evidence; acc@10 is unaffected because the answer text still reaches the
top 10 context.

## Variants tried and dropped

- **Rerank without the history skip** (w 0.5, top 20/30/50): fixtures 0.953 /
  0.871, holdout 0.913 / 0.785. Fixed by the skip above.
- **Path-chain rerank** (cross-encoder over the concatenated fact text of the best
  6 or 12 semantic path chains, blended into the chain score before `evidence`):
  multihop-holdout acc@10 0.825 -> 0.825 (two-hop 0.825 -> 0.850, three-hop 0.720
  -> 0.680), MRR 0.812 -> 0.812 / 0.804; fixtures and holdout unchanged. Extra
  cost, no gain; code removed.
- **Chain-exempt rerank** (candidates found by the `path` / `sem` channels keep full
  relevance credit, w 0.5, top 20/30/50): world-300 recall 0.965 -> 0.989 / 0.990 /
  0.990 (MRR 0.886 / 0.885 / 0.885) and multihop-holdout recall 0.706 (MRR 0.833),
  but fixtures 0.939 / 0.931 / 0.929 recall and 0.863 / 0.850 / 0.848 MRR, holdout
  0.801 / 0.785 / 0.754 recall and 0.721 / 0.717 / 0.711 MRR. Rejected by the
  fixtures and holdout gate; not run on multihop-holdout2 (its six configs were
  spent). Code removed.
- Fact-sentence reranking was not built: `acc@10` reads every returned fact, so
  reordering the 8 facts cannot change it; enlarging the fact pool would be a
  separate change.

## Latency (world-300 and multihop-holdout, same session)

The machine was shared with other lane workers (load average 10-80 on 12 cores),
so wall-clock numbers are noisy; configs were run interleaved (main, off, top 20,
top 30, top 50 per round, two rounds, same saved DB) and the CPU-time table below
is the load-robust cost. `main` is a pristine build of base `5270b44`; `off` is
this branch with `rerank_top = 0`.

Wall clock per recall, ms, mean of two rounds (`w_rerank` 0.5):

| set | config | p50 | p95 | mean | p50 vs main |
|---|---|---|---|---|---|
| multihop-holdout (80 q, every query reranks) | main | 112.4 | 524.2 | 218.3 | - |
| | off | 112.3 | 133.3 | 136.0 | -0.1% |
| | top 20 | 275.0 | 321.5 | 345.9 | +145% |
| | top 30 | 459.2 | 642.2 | 450.5 | +308% |
| | top 50 | 757.1 | 1026.9 | 767.5 | +574% |
| world-300 (600 q; 180 history / as-of queries skip the rerank) | main | 199.1 | 307.4 | 229.8 | - |
| | off | 200.4 | 795.5 | 290.4 | +0.7% |
| | top 20 | 365.1 | 732.1 | 409.3 | +83% |
| | top 30 | 403.2 | 718.0 | 456.3 | +103% |
| | top 50 | 527.7 | 889.9 | 541.1 | +165% |

(The `off` p95 of 795 ms comes from one round at 1295 ms during a load spike; its
other round is 296 ms. `off` and `main` are the same code path plus one branch.)

CPU time per recall (user + sys, all threads, from 80 queries minus a 1-query
run of the same process, multihop-holdout, two rounds), seconds:

| config | round 1 | round 2 |
|---|---|---|
| main | 0.462 | 0.436 |
| off | 0.489 | 0.485 |
| top 20 | 1.191 | 1.178 |
| top 30 | 1.452 | 1.547 |
| top 50 | 2.266 | 2.140 |

That is roughly +0.7 s (top 20) to +1.7 s (top 50) of CPU per recall, about 35 ms
of CPU per reranked candidate on these ~25-40 token memories; wall clock is that
divided by the usable cores. Any rerank is far above the 10% latency budget.

Cold start (one query in a fresh process, includes loading UltraBERT; median and
range of 5 runs): main 362 ms (348-525), off 356 ms (339-556), top 30 664 ms
(643-1236). The reranker adds ~300 ms once per process (mmap of the 91 MB file,
tokenizer, first forward); the MCP server pays it on the first reranked recall.

## Reproduce

```bash
export NEOCORTEX_MODEL_DIR=.../UltraBERT-Embed-150M NEOCORTEX_RERANK_MODEL=.../ms-marco-MiniLM-L-6-v2
neocortex eval eval/holdout.json --save-db /tmp/h.db
neocortex eval eval/holdout.json --load-db /tmp/h.db --set w_rerank=0.5 --sweep rerank_top=0,20,30,50
cargo test --test rerank -- --nocapture      # parity (needs the model dir)
```

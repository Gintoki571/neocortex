# DOX framework

- DOX is highly performant AGENTS.md hierarchy installed here
- Agent must follow DOX instructions across any edits

## Core Contract

- AGENTS.md files are binding work contracts for their subtrees
- Work products, source materials, instructions, records, assets, and durable docs must stay understandable from the nearest applicable AGENTS.md plus every parent AGENTS.md above it

## Read Before Editing

1. Read the root AGENTS.md
2. Identify every file or folder you expect to touch
3. Walk from the repository root to each target path
4. Read every AGENTS.md found along each route
5. If a parent AGENTS.md lists a child AGENTS.md whose scope contains the path, read that child and continue from there
6. Use the nearest AGENTS.md as the local contract and parent docs for repo-wide rules
7. If docs conflict, the closer doc controls local work details, but no child doc may weaken DOX

Do not rely on memory. Re-read the applicable DOX chain in the current session before editing.

## Update After Editing

Every meaningful change requires a DOX pass before the task is done.

Update the closest owning AGENTS.md when a change affects:

- purpose, scope, ownership, or responsibilities
- durable structure, contracts, workflows, or operating rules
- required inputs, outputs, permissions, constraints, side effects, or artifacts
- user preferences about behavior, communication, process, organization, or quality
- AGENTS.md creation, deletion, move, rename, or index contents

Update parent docs when parent-level structure, ownership, workflow, or child index changes. Update child docs when parent changes alter local rules. Remove stale or contradictory text immediately. Small edits that do not change behavior or contracts may leave docs unchanged, but the DOX pass still must happen.

## Hierarchy

- Root AGENTS.md is the DOX rail: project-wide instructions, global preferences, durable workflow rules, and the top-level Child DOX Index
- Child AGENTS.md files own domain-specific instructions and their own Child DOX Index
- Each parent explains what its direct children cover and what stays owned by the parent
- The closer a doc is to the work, the more specific and practical it must be

## Child Doc Shape

- Create a child AGENTS.md when a folder becomes a durable boundary with its own purpose, rules, responsibilities, workflow, materials, or quality standards
- Work Guidance must reflect the current standards of the project or user instructions; if there are no specific standards or instructions yet, leave it empty
- Verification must reflect an existing check; if no verification framework exists yet, leave it empty and update it when one exists

Default section order:
- Purpose
- Ownership
- Local Contracts
- Work Guidance
- Verification
- Child DOX Index

## Style

- Keep docs concise, current, and operational
- Document stable contracts, not diary entries
- Put broad rules in parent docs and concrete details in child docs
- Prefer direct bullets with explicit names
- Do not duplicate rules across many files unless each scope needs a local version
- Delete stale notes instead of explaining history
- Trim obvious statements, repeated rules, misplaced detail, and warnings for risks that no longer exist

## Closeout

1. Re-check changed paths against the DOX chain
2. Update nearest owning docs and any affected parents or children
3. Refresh every affected Child DOX Index
4. Remove stale or contradictory text
5. Run existing verification when relevant
6. Report any docs intentionally left unchanged and why

## User Preferences

When the user requests a durable behavior change, record it here or in the relevant child AGENTS.md

# neocortex AGENTS.md

## Purpose

Long-term memory for AI agents, v0.1.4. Rust, one crate, one binary `neocortex` (CLI + MCP stdio server). One SQLite file holds memories (FTS5 BM25 + sqlite-vec), an entity/relation knowledge graph (graphqlite projection) and bi-temporal facts. Embeddings: UltraBERT-Embed-150M on candle (pure Rust, CPU). No LLM inside, no Python at runtime (offline tooling only, in `scripts/` and `eval/extract/reference/`), no network.

Target hardware (binding, user requirement 2026-10-26): neocortex must run well in low-resource environments: old CPUs (few cores, no recent SIMD extensions assumed) with 2-3 GB of total RAM, such as cheap VPSes and old laptops; the agent and the OS share that RAM. Every change is judged on accuracy AND footprint: peak RSS, cold start, recall/remember latency on 1-2 cores, model and DB size on disk. Builds for other platforms (ARM, Android) are out of scope for now. Working budget: peak RSS well under 512 MiB during cold recall and remember; f32 cannot meet it (615 MiB), q8 does (see Verification). Footprint numbers live in Verification and `docs/research/footprint.md`.

Design (binding): `docs/superpowers/specs/2026-10-22-neocortex-design.md`. Plan: `docs/superpowers/plans/2026-10-23-neocortex-plan.md`. Pre-rewrite ReMem code: git tag `remem-final`.

## Ownership

- Orchestrator/validator: Claude (merges lanes, runs gates, owns this file and the design doc).
- Lanes (external harness agents) own only the files named in their brief, on branch `lane-<name>` in a git worktree under `../neocortex-lanes/<name>`.

## Local Contracts

- Version stays `0.1.4` until the user says otherwise.
- Tests that create temp files or directories use `tests/common/mod.rs` `TempDir` (std only; removed on drop, also on panic). Never leave a `neocortex-*` path under the system temp dir without a guard. `src/import.rs` unit tests share it via `#[path]`.
- Dependencies: rusqlite (bundled), sqlite-vec `=0.1.9` (0.1.10-alpha does not compile), graphqlite `0.12`, candle-core/candle-nn `0.11`, tokenizers (`fancy-regex`, no default features), serde, serde_json. Adding any other crate needs a one-line reason here.
- Relational tables are the source of truth; graphqlite nodes/edges are a projection rebuilt by `neocortex reindex`.
- Vector storage mode (`db::VecMode`): the four vec0 tables (`memories_vec`, `entities_vec`, `predicates_vec`, `relations_vec`) are `float[768]` (f32) or `int8[768]` (int8: each vector scaled so its largest element is 127; cosine is scale-invariant, and `decode` renormalises to unit length). New databases take `NEOCORTEX_VEC` (default f32); the mode is `schema_meta.vec_mode`, kept on every open. Every vec0 bind goes through `db.vec_sql("?n")` (int8 needs sqlite-vec's subtype), every blob write through `db.vec_blob`, every read-back through `db.blob_to_vec` (dequantises); cosine math stays f32. `neocortex migrate-vectors --to int8` rewrites in one transaction, then VACUUM (f32 is the only source). Default stays f32: on 8af053c + lane, int8 holds fixtures (0.953/0.895), multihop (0.825), multihop2 (0.830) and world-300 (0.992 acc@10) but holdout MRR is 0.792 against the 0.793 floor (f32 0.794). world-300 DB 21.3 MB -> 8.9 MB.
- One connection per process (`db::Db`): sqlite-vec via `sqlite3_auto_extension`, graphqlite via `Connection::from_rusqlite`. Writes go through `Db::write` (BEGIN IMMEDIATE). Cypher runs inside the same transaction.
- Validity is half-open `[valid_from, valid_to)`; system retirement is `expired_at`. Times are unix seconds UTC.
- One live memory per `content_hash` (unique partial index); a hash hit only counts as a duplicate when kind + folded text match. A memory's end (`--until`, `invalidate m`, supersede) ends the relations it alone still evidenced; soft forget retracts them (`expired_at`, no end date); hard forget and merge patch the graph projection incrementally, never `rebuild_all`.
- ER-07 near-name dedup is layered: JW on the comparison key only (`text::translit_norm` is never stored), then hard blockers (`text::name_blocker`: differing digit-bearing tokens (whole token, so "Apt 3B"/"Apt 3C" differ; EX-01), whole names < 4 chars, strict token-set subset, differing-token short labels < 4 chars, single-token prefix extension with a >= 2-letter tail, differing multi-token tokens both >= 4 chars and JW < 0.85), then the typo-edit gate (`text::name_typo_ok`: the differing token keys must be within a Damerau-Levenshtein allowance, <= 1 edit up to 8 chars and <= 2 beyond; "Wisniewski"/"Wisniowski" (1 edit, 10 chars) stays mergeable - see Config doc), and only then the entity-cosine gate reuses `entity_conflict` as a veto (semantic embedder only; hash embedders decide on the name layer alone; an agreeing cosine never causes a merge - "Bergen Airport South" is not "Bergen Airport" even when every vector agrees). At `name_merge = 0.92` (2026-10-25 measured, 51 labelled pairs in `tests/data/name_pairs.json` via `examples/name_eval`): recall 0.964, precision 0.964 - the one recall miss is "Aleksandr Ivanov"/"Alexander Ivanov" (4 key edits on 9-char tokens) which lands Near; the one false merge is "Wisniewski"/"Wisniowski" (1 edit on 10-char keys, name-layer isomorphic to Достоевский/Dostoevsky). `name_near = 0.85` splits Near (reported, never merged; over-allowance pairs land here even above `name_merge`) from Below (silent). Merge resolves with status "near" (alias origin "near"); Near/Blocked/Unsure create a new entity with status "ambiguous" + candidates, never silent.
- Q-08: `lookup_entity_fuzzy` gained a JW stage (after prefix, before vector) on the same `name_merge` threshold and blockers; it requires >= 4 chars and falls through when two entities win within 0.005.
- Embedding-only similarity never merges entities; it only adds `similar` soft edges.
- Write-time alias prefix (EX-04, `resolve::unique_prefix`): after the exact stage, a mention of >= 3 chars that prefixes the alias of exactly one entity (same type filter as `exact_ids`) resolves to it with status "alias" and alias origin "prefix", but only when that alias continues the mention after a separator ("ultrabert" + "-embed-150m"). A space or letters ("paris" + " tx", "alex" + "is") are sibling names and fall through to the candidate stages, as do two or more entities. This is stricter than the read-side `lookup_entity_fuzzy` prefix stage on purpose: the write path merges, and "Paris" must not merge into "Paris TX".
- Heuristic entities (EX-01..03, `extract::heuristic_entities_with`): a head noun from `UNIT_HEADS` (Apt, Suite, Room, Gate, Unit, Building, ...) followed by a label ("3B", "B12", "210") is one entity ("Apt 3B", "Suite 210"); the head is then never a span member, so "Harbor Building 7" splits into "Harbor" and "Building 7". A `UNITS` word (MB, ms, KiB, ...) right after a number is never an entity. A two-word span whose first word is known (alias lookup) and whose compound is not, followed by a `SPAN_NOUNS` plural ("Cypher Memory nodes"), yields the first word only; a closed noun list keeps verbs from splitting real names. `remember` passes the alias lookup as `known`; `heuristic_entities` (no DB) passes none.
- Ids shown to agents: `m<id>`, `e<id>`, `r<id>`; tools accept both forms.
- `recall` adds a query-directed path channel (`paths::search`, beam 24, depth 3, `PATH_WEIGHT` 2.5) plus a semantic multi-hop channel (`paths::search_semantic`: relation KNN k=100, residual-question hop scoring, >= 2-hop chains, weight `w_sempath` 0.25) and renders the path facts (the best lexical and the best semantic chain both reach the facts); the lexical beam is skipped on history-intent questions and both beams on negation questions. Up to three chains are rendered (`paths::top_chains`: best lexical, best semantic, next lexical; `facts` limit 8). Opt-in (`Config.prose_margin`, default infinity = off; `eval --set prose_margin=0`): when the best semantic chain uses prose (relation-less) memories and beats the best chain with another terminal by that margin, up to two of those memories are rendered first in `facts` as `[m<id>] <bridge entity> · <text>` (`FactHit.memory`; `paths::prose_facts`). Measured: off, Q1 + `top_chains` give mh2 +2; margin 0 adds +1 more on mh2 but no gain on a private blind set and +1.5% to +4.5% context tokens, so it stays off. An empty recall is returned when no lexical, entity, relation or path support exists and the best cosine is below `ABSTAIN_COSINE` (0.18).
- `recall` also reports unfinished hops in `next: Vec<NextHop>` (`{entity, name, want, why}`, at most two, omitted when empty; `entity` + `want` feed `follow`). A hint appears when the best chain's last hop does not match the question's wh-frame, or when no chain covers the asked relation; it is suppressed when the frame already matches the returned facts/memories (lexical cue guard before the frame embedding, then cosine >= `hint_tau`). `hint_tau` defaults to 0.40 and `0` disables hints; hints never change ranking or the scored context, and average well under 30 extra output tokens per recall.
- Two optional channels are measured experiments and default to 0: `tlink` (`w_tlink`; temporal links are always written between memories within `tlink_window_hours` that share an entity, weight `max(0.3, 1-gap/24h)`, at most `tlink_cap` per endpoint) and `causal` (`w_causal`; only on why-intent questions, over the seeded `cause` group; `causal_extract` optionally adds one conservative in-memory text-cue relation when the agent supplied none).
- Access is recorded for every memory `recall` returns, in one `Db::write` transaction (`access_count`/`last_access` totals plus `memory_access` timestamps, capped by `access_keep`; `0` keeps no history). `w_retention` (default 0.05: neutral on fixtures/world/multihop-holdout2, +0.007 MRR on holdout) blends `rank::retention` into ranking; `stats.cold_memories` is a report-only hint (retention < 0.15).
- Communities are deterministic Leiden (`graph::leiden`, seed 7, resolution 1.0) over the live weighted snapshot (memories, entities, mentions, live relations, similar). Ids are remapped to the previous run by greedy member overlap, so `[cN]` stays put while the graph only grows. `overview` and the `entity` card read the table; recall scoring does not, so communities never move retrieval scores.
- `Config.hop_scorer` (`off` default | `on`; `eval --set hop_scorer=on`) replaces the semantic beam's residual cosine with the learned logistic hop scorer (`HOP_WEIGHTS`/`HOP_BIAS` in `src/paths.rs`, retrained only by `scripts/train_hop_scorer.py`). Kept off: no multihop gain (2026-10-26, `docs/research/multihop.md` section 8). Hop features are built only when the scorer or the dump is on.
- `Config.anchor_tiers` (default empty = exact aliases only; `eval --set anchor_tiers=1b`) adds query-anchor tiers in `src/anchor.rs`: `w` demotes generic or shared aliases (one word not in the entity's own name, or an alias naming several entities) to weak anchors, `1` makes a capitalised non-initial query word that is the first/last word of exactly one multi-word entity name a weak anchor, `2` resolves a role noun next to an anchor through its one live relation; weak anchors seed PPR and start both beams, and only `b` (block pass-through) / `x` (enable prose hops) / `p` (both) give them the strong-anchor side effects. Kept off: every config tested on multihop-holdout2 (`w`, `w1`, `w1b`) scored 0.820 vs main 0.830 on the same DB; `1b` (fixtures/holdout unchanged, multihop-holdout 0.825 -> 0.8875) was not run on it (2026-10-26, lane nc-anchor).
- Text-only retraction: when a write has no relations and its text carries a `RETRACTIONS` cue, `remember` matches names (memory entities, heuristic candidates, alias n-grams) against live relations of that group and ends the single match at `valid_from` (reported in `invalidated`); several matches return `conflicts` and end nothing. A live row recorded at ingest time matches even when the text dates the retraction earlier ("divorced ... in 2024"): a recorded start at or after that date is system-retired (`valid_to` = start, `expired_at`), while an already-ended row must contain the date. The name must be the whole object of the cue: a determiner between cue and name, a possessive, a ditransitive object or a following noun rejects it, and only a clause boundary, a time expression or an employment tail ("to join", "for <Entity>") may follow; the employment pattern includes "left his/her/their job|position at X". A hedge or report in the clause (`almost`, `might`, `thinks`, `said that`, ...) returns the match as `conflicts` and ends nothing. Plans (`will`, `going to`, `plan to`, `next <unit>`, `in N <unit>`) resolve a future `valid_from` via `temporal::future_window` or get the tag `planned`; `recall` drops `planned`/future rows unless the query asks for plans or its window starts in the future. Recurrence cues tag `recurring` and keep the rule text. Ordering/duration intent sorts memories and facts by `valid_from` and fills `duration` (calendar units, "ongoing since …").
- The embedder sets `RAYON_NUM_THREADS` to candle's thread count at model load when unset (gemm and rayon pools must agree; 2x faster).
- Env: `NEOCORTEX_VEC=f32|int8` (vector mode of a new database only), `NEOCORTEX_EMBEDDER=hash` (tests only; a DB records its embedder and refuses another), `NEOCORTEX_DB` (default `~/.neocortex/neocortex.db`), `NEOCORTEX_MODEL_DIR` (default `~/.neocortex/models/UltraBERT-Embed-150M`), `NEOCORTEX_EMBED_DTYPE` (`f32` = `model.safetensors`, `q8` = `model.q8_0.gguf`, `q4k` = `model.q4_k.gguf`; unset = f32 when the safetensors exists, else q8; see the embedder dtype contract), `NEOCORTEX_TZ` (`+HH:MM`, default system local offset), `NEOCORTEX_RERANK_MODEL` (default `~/.neocortex/models/ms-marco-MiniLM-L-6-v2`, optional), `NEOCORTEX_RERANK` (`<N>` / `off`, overrides `Config::rerank_top`), `NEOCORTEX_MAX_TOKENS` (default 1024), `NEOCORTEX_EXTRACTOR` (unset = off; `rules` = `src/extract_model.rs` relation/date tier, used only when a memory has no agent-supplied entities or relations), `NEOCORTEX_DUMP_HOPS=<file>` (appends one JSON line per candidate hop the semantic beam scores: features, evidence memory ids; training data only).

## Layout

- `src/db.rs` + `src/schema.sql` - connection, extensions, schema. The vec0 tables are created by `db::create_vec_tables` (not schema.sql) so their element type follows the vector mode. The schema version lives in the `schema_meta` table (v4), never in `PRAGMA user_version`: graphqlite owns that pragma (it stamps 1 and its cypher executor refuses any other value). Migrations are an explicit ladder in `Db::init` (v4 owns every pre-f2 predicate shape: the committed baseline stamps v3 with a three-column `predicates` table); the seeded predicate ontology (21 rows: `predicates.display/group_id/inverse_of/symmetric/seeded`) is re-seeded idempotently, and seeded `exclusive` is not agent-settable. `memory_links` (E4a) and `memory_access` (E5) are additive tables ensured by `Db::ensure_additive_tables` on every v4 open; the schema version stays v4, and a missing `cause` anchor re-seeds the causal family so existing databases gain it. B5 adds two more additive tables the same way: `name_tokens(token, entity_id)` (the token set of `entities.norm`, written on insert and backfilled once on the first open of a database that predates it) and `name_part(a, b, weight)` (undirected containment links, `a < b`, weight 0.6). New databases declare `chunk_size=64` on all four vec0 tables (the 1024 default reserves 12.6 MiB on the first insert); existing databases keep the chunk size they were created with, since `CREATE VIRTUAL TABLE IF NOT EXISTS` never rewrites them.
- `src/embed.rs`, `src/ultrabert.rs` - Embedder trait, UltraBERT forward pass, HashEmbedder (tests), dtype selection (`load_dtype`, `weights_file`, `identity`) and the offline conversion (`quantize_dir` -> `ultrabert::quantize_model`, CLI `neocortex quantize-model <f32 dir> <out dir> [--dtype q8|q4k]`). Weights are read tensor by tensor with plain file reads straight into their final buffer (`SafetensorsFile`; q/k/v and gate/up are read back to back into one fused buffer): peak RSS is one copy of the weights (615 MiB f32; the old mmap + `Tensor::from_slice` + `Tensor::cat` path peaked at 1,190 MiB), the page cache is not charged. candle tensors own their storage (`CpuStorage` is a `Vec`), so nothing can be built zero-copy from an mmap. The quantized model is a GGUF with Q8_0 (or Q4_K) linear weights stored fused (`layers.N.qkv.weight`, `layers.N.gate_up.weight`), a Q8_0 embedding table and f32 norms. Quantized layers are dequantized to f32 in 256-row slabs (`quant_matmul`, L2-resident) and multiplied by the same runtime-dispatched gemm as f32 (AVX2 copy of the dequant loop chosen by `is_x86_feature_detected!`, baseline loop elsewhere): activations stay f32, so q8 error is weight rounding only. candle's own `QMatMul` is not used: its SIMD kernels are chosen at compile time (`target_feature = "avx2"`/`"neon"`), the default x86-64 build falls to scalar code and measured 14 s per recall instead of 0.25 s. No bf16/f16 weights: f16 gemm measured 1.6x slower than f32 and f16 -> f32 conversion 1.2x slower than gemm itself. Cold CLI recall is dominated by reading the weights plus the tokenizer JSON parse (~30 MiB, ~155 ms).
- Embedder dtype contract: the DB-recorded embedder name (`embed::identity`) is the model, not the dtype. f32 and q8 share `ultrabert-150m` because their vectors are interchangeable (measured: cosine q8 vs f32 over 927 eval texts min 0.99836 / mean 0.99959; a DB ingested with f32 queried with q8 scores the same retrieval); a dtype joins that identity only while its parity holds (>= 0.995 mean, >= 0.99 min on `tests/embed_quant.rs`). `q4k` (mean cosine 0.953, min 0.929) fails that bar and has its own name `ultrabert-150m-q4k`, so a DB refuses the other dtype. Default stays f32 (full accuracy, fastest warm path); q8 is the choice for machines under ~1 GB of free RAM. Never ship a build with `-C target-cpu=native` or a required AVX2/AVX-512/FMA flag: SIMD is runtime-dispatched or portable.
- `src/text.rs` - normalisation, singularise, Jaro-Winkler, trigrams, FTS query building, predicate keys, content hash. Greek accents fold (tonos/dialytika, ς→σ, ё→е); `translit_norm` builds the ER-07 comparison key (Cyrillic→Latin, ю deliberately as "u", German ue/oe/ae digraphs, Slavic endings ky→ki/ow→ov); `name_blocker` is the ER-07 hard-blocker list.
- `src/temporal.rs` - civil dates, instant/window parsing, query windows, history intent, plan/recurrence/ordering/duration cues and calendar duration formatting.
- `src/extract.rs` - heuristic entity candidates, n-grams for alias lookup. S-03: Unicode-aware capitalisation (`is_acronym`, single capitals, `is_foreign_title_case`) keeps cased non-Latin scripts (Latin diacritics, Greek, Cyrillic, Armenian); caseless scripts (CJK, Arabic) are a documented limit. Calendar/clock/year/duration/ordinal/relative-time spans are rejected (`is_date_like_name`). B5: `CONNECTORS` (`do, da, dos, das, de, del, della, di, du, van, von, der, la, le, of`) stay inside a proper-noun span; a possessive ("Nova's") ends a multi-word span and is stripped from its name ("Universidade Nova", the head after it is a separate span), so "Rua do Instituto Bacteriológico" and "Universidade da Beira Interior" are one entity each and a generic head is never emitted alone; `is_hyphen_tail` keeps a hyphen-glued compound ("cryo-ET", "C-Class") from starting a span ("ET of Lon" is not a name). EX-05: a sentence-initial single word is kept when `known` (a stored alias) or when `VERB_CUES` (`is, was, has, had, runs, said, joined, moved, lives, works`) follows and the word is not ordinary/status, not a `COMMON_NOUNS` entry (shortcut: fixed general list) and does not appear lowercase elsewhere in the memory ("Paris is the capital", "Cypher runs"; "Protein is split" is not a name).
- `src/extract_model.rs` - optional deterministic relation/date tier (off by default). `causal_cue` is the conservative single-cue "A because B" extractor used by E4b. Scored by `examples/extract_eval.rs` on `eval/extract/gold.json` (128 memories; `cargo run --release --example extract_eval -- [gold] [predictions.json] [name]`). Reference predictions and runner scripts: `eval/extract/preds/`, `eval/extract/reference/`. Comparison and candle port plan: `docs/research/extraction.md`.
- `src/graph.rs` - CSR + ACL push personalized PageRank, deterministic Leiden community detection (seeded XorShift visit order, refinement with connected-component splits, aggregation carrying collapsed self-loop weight) and Newman modularity. `src/rank.rs` - RRF, MMR, cosine, packing, and `retention` (E5 score).
- `src/remember.rs`, `src/resolve.rs`, `src/kg.rs` - write pipeline, entity/predicate resolution, and rebuildable graph projection. `remember` and `remember_batch` share `prepare` + `write_prepared`; a batch chunk of <= 256 inputs is one embed call and one transaction with a SAVEPOINT per item. `write_prepared` also writes E4a temporal links. Entities are unique on `(norm, type, homonym)` (types lower-cased); homonym pools resolve by card cosine + memory-context cosine; inverse writes are stored in the canonical predicate direction, symmetric ones once with `src < dst`; negation (`polarity=0`) ends the same `(src, dst, group)` positive interval; exclusivity and conflicts key on the predicate group (`relations.subj`, `predicates.group_id`); the REL-19 exclusive-ending block queries the value side (the non-subject endpoint, so inverted predicates like "reports to" stored as "manages" end correctly) and asks `resolve::near_name`: Below ends the old fact, Merge skips silently, Near/Blocked/Unsure skip and push a `Conflict{relation_id, fact, valid_from}`; relation phrase vectors use `pred_alias = 0.80` with head/tail guards; stale `predicates_vec` is wiped by the v4 migration. B5: `insert_entity` writes the entity's `name_tokens` and calls `link_name_parts`, which finds entities whose exact token set (`text::exact_name_tokens`, unsingularised) strictly contains or is contained in the new name (one indexed token probe, candidate cap 200); the contained side must be a place by type (`PLACE_TYPES`), the container a place or org (`ORG_TYPES`; org inside org never links), no person on either side, and it writes one `name_part` row; `enrich` re-runs it when a later mention fills in an untyped entity's type; the `CONTAINS` edge is projected by `kg::project_name_parts` after `project_entity_from_db`, because the write path links a new entity before its node exists; `merge_entities` moves the merged entity's links and tokens to the survivor like `similar` edges.
- `src/recall.rs` - ranked multi-channel memory, fact, and entity retrieval (base channels plus optional `tlink`, `causal` and retention blend), `overview` community cards (label = top-degree names, size, key predicates, date span, central facts) and the optional `community` field on `entity` cards; `lookup_entity_fuzzy` has a JW stage on the ER-07 `name_merge` threshold and blockers (Q-08); `next_hops` builds the wh-frame hints (`WhFrame`, `relation_matches_frame`, chain-end and seed bridges); `src/eval.rs` - fixture-based retrieval evaluation and ablations.
- `src/paths.rs` - LLM-free query-directed path search over relations (lexical channel `path`) and the semantic beam (channel `sem`: residual-question hop scoring over recognised facts, plus text-only memories as prose hops and B5 name-containment links as `NAME_PART_HOP` 0.6 hops scored by the target card vector, never passing through a question anchor), plus the agent tools `follow` (bounded traversal, `reached` flag) and `aggregate` (grouped counts with a `negative` bucket). Also owns negation cues (`has_negation_cue`, `negation_intent`), why-intent (`causal_intent`) and causal evidence (`causal_memories`).
- `src/anchor.rs` - query anchors (`query_anchors`: strong exact aliases, weak tiers, the pass-through block list and the prose-hop switch passed to `paths::search_semantic`). `tests/anchor.rs` - tier behaviour: unique first name, shared first name, lower-case common noun, generic/shared alias demotion, role noun via a relation, first-name anchor starting the path channel.
- `src/rerank.rs` - optional cross-encoder reranker (`Reranker` trait, `LazyReranker`, ms-marco-MiniLM-L-6-v2 BERT forward pass on candle, `blend`). `recall` reranks the top `Config::rerank_top` fused candidates (0 = off) and skips history / as-of queries; an absent or broken model leaves recall byte-identical.
